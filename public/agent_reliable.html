Research statement · 29 October 2026

Learning Reusable Reasoning for Reliable AI-Assisted Programming

Scope
Program reasoning and coding agents for unfamiliar codebases and extended software tasks.
Aim
Develop reasoning that transfers to new programs and methods that preserve reliability across multiple software changes.

My research examines how AI coding agents adapt to unfamiliar codebases and maintain reliability as software tasks grow in scope. Repairing a library function requires understanding its behavior and identifying the cause of a failure. Extending that repair across callers, dependencies, and later versions requires preserving the requirements of the larger system.

I pursue two connected directions. Learning reusable reasoning concerns how models acquire strategies that transfer to new programs. Building reliable coding agents concerns how agents apply those strategies across multiple changes while maintaining required behavior. Together, these directions connect learning at the level of individual programming decisions with reliability across an entire software task.

Both directions involve informal and formal reasoning. Informal reasoning draws on bug reports, documentation, and code observations to interpret requirements and propose explanations. For example, an agent may use a failing execution to infer that a boundary condition is incorrect, then design a test to investigate that explanation. Such evidence supports diagnosis but is limited to the cases examined.

Formal reasoning expresses a requirement precisely and checks it against an explicit model of program execution. For example, a verifier can translate an array-bounds requirement into logical conditions that a proof must establish. The Verus proof-development workflow illustrates how agents can use verifier feedback to construct these proofs. Informal reasoning helps determine which claims matter; formal reasoning establishes specified claims under stated assumptions. Proof failure may remain inconclusive, and proof acceptance does not establish that the specification fully captures the intended behavior.

Two connected directions
  1. Learning reusable reasoning for programming
  2. Building reliable coding agents

Research direction 1

Learning reusable reasoning for programming

How can models learn reasoning strategies that generalize to unfamiliar programs?

Reasoning guides how an agent investigates unfamiliar code: which explanation to test, which assertion to introduce, and when to revise a proposed solution. I use reusable to describe strategies that remain useful across different programs. My prior work provides an empirical starting point. The Loop-R1 preprint reports improved synthesis of loop invariants—properties preserved across loop iterations—after training with reasoning data, although performance on more complex programs remains limited. Our execution-trace study found limited benefits from supplying trace information in its evaluated settings. These findings motivate examining how models learn to use feedback, rather than assuming that access to additional evidence is sufficient.

I hypothesize that training on reasoning decisions and their evaluated outcomes improves transfer beyond training on final solutions alone. I would test this through loop-invariant revision, followed by debugging and repair, using held-out program families and matched resources. Evaluation would measure independently assessed correctness and total cost, with separate comparisons for retrieval and additional search. The aim is to establish whether models learn strategies that remain effective on new programs.

Research direction 2

Building reliable coding agents

How can agents preserve required behavior across larger and longer software tasks?

Reliable reasoning on one function does not by itself ensure that a sequence of changes preserves system requirements. An edit may affect callers, alter a dependency, or invalidate an earlier conclusion. The verified-stack roadmap proposes reusing component proofs through verified interfaces, highlighting the role of shared assumptions in larger software guarantees. Building on this perspective, I would study how coding agents coordinate related changes, recognize when earlier evidence no longer applies, and recover from unsuccessful actions.

I hypothesize that revising plans and rechecking affected assumptions after software changes can reduce regressions during extended tasks. I would compare adaptive planning and checking with fixed policies under matched tool access and budgets, increasing task duration and component interaction. Independent evaluation would measure completion, regressions, recovery, and human review effort against the same requirements. The study would determine whether improved reliability justifies the additional checking cost; formal guarantees would remain conditional on the specified properties and assumptions.

My long-term goal is AI systems that learn to solve unfamiliar programming problems and produce software people can depend on. The first direction develops transferable reasoning; the second examines whether agents can use it reliably as software tasks expand.

Research foundation

My work in code-model evaluation, program repair, and loop-invariant synthesis provides the foundation. Related projects include Loop-R1, Defects4C, RATCHET, and execution-trace evaluation. The learning and agent methods described above are proposed research.

Related verification work provides concrete context: Anthropic and Theorem describe proofs of specified software properties under explicit execution assumptions; Theorem’s verified-stack proposal emphasizes reuse through verified component interfaces; and the Verus guide motivates protecting specifications and checking for invalid proof shortcuts.
