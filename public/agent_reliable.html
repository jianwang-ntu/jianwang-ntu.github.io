Research statement · 29 October 2026

Learning Reusable Reasoning for Reliable AI-Assisted Programming

Scope
Program reasoning and coding agents for unfamiliar codebases and extended software tasks.
Aim
Develop reasoning that transfers to new programs and methods that preserve reliability across multiple software changes.

An AI coding agent entering an unfamiliar codebase must determine what the software is intended to do, how it behaves, and which changes would solve the task. Consider repairing a library function: a plausible edit is only a starting point. The agent must investigate the failure, choose checks that distinguish possible causes, and revise its solution when the evidence disagrees. If the repair also changes callers or dependencies, it must then preserve the requirements of the wider system.

My research addresses these challenges through two complementary directions: learning reasoning strategies that transfer to unfamiliar programs, and building coding agents that remain reliable across extended tasks and changing contexts. The first asks what models can learn from solving programming problems. The second asks how agents can use their capabilities dependably as changes accumulate and earlier conclusions need reconsideration.

Both directions combine informal and formal reasoning within the same software task. Informal reasoning draws on requirements, documentation, code, and observed executions to propose explanations and decide what to check. Tests and traces provide empirical evidence about the cases examined. Formal reasoning makes a claim precise and establishes it relative to a specification, execution model, and assumptions. The Verus proof-development guide illustrates how verifier feedback can guide proof construction. A failed proof attempt does not by itself establish a software defect; a successful proof supports the specified claim, whose relevance still depends on how faithfully it captures the intended behavior.

Two connected directions
  1. Learning reusable reasoning for programming
  2. Building reliable coding agents

Research direction 1

Learning reusable reasoning for programming

How can models learn reasoning strategies that generalize to unfamiliar programs?

Reasoning is reusable when a strategy learned on one program helps solve another—for example, identifying the condition a loop must preserve or choosing a check that distinguishes competing explanations of a failure. My prior work offers a starting point for studying this transfer. The Loop-R1 preprint reports improved loop-invariant synthesis after training with reasoning data, while performance remains limited on harder programs. Our execution-trace study found limited gains from trace information in its evaluated settings. These findings motivate studying how models learn to interpret and act on evidence; they do not establish that the resulting strategies generalize broadly.

I hypothesize that training on proposed solutions, the checks used to assess them, and revisions linked to the observed results can improve transfer beyond training on final solutions alone. I would test this on unfamiliar program families in invariant synthesis and program repair, comparing independently assessed correctness and computational cost under matched resources.

Research direction 2

Building reliable coding agents

How can agents preserve required behavior across larger and longer software tasks?

Transferable reasoning alone cannot ensure reliability across a larger software task. An agent may solve each immediate problem plausibly while introducing incompatible changes or relying on assumptions that no longer hold. The research question therefore extends from making an individual decision to coordinating decisions over time. Theorem’s verified-stack roadmap proposes reusing component proofs through verified interfaces, illustrating why larger guarantees depend on relationships between components. More broadly, I aim to understand how coding agents recognize the consequences of their changes, reconsider earlier decisions, and recover when an approach fails.

I hypothesize that adapting plans and checks as software changes can reduce regressions during extended tasks. I would compare adaptive and fixed approaches under matched tool access and budgets, independently assessing task completion, preserved behavior, and recovery as tasks span more components and revisions.

My long-term goal is AI-assisted programming that combines the ability to solve unfamiliar problems with dependable execution of larger tasks. These directions address both what an agent learns and how reliably it puts that learning to work.

Research foundation

My work in code-model evaluation, program repair, and loop-invariant synthesis provides the foundation. Related projects include Loop-R1, Defects4C, RATCHET, and execution-trace evaluation. The learning and agent methods described above are proposed research.

Related verification work provides concrete context: Anthropic and Theorem describe proofs of specified software properties under explicit execution assumptions; Theorem’s verified-stack proposal emphasizes reuse through verified component interfaces; and the Verus guide motivates protecting specifications and checking for invalid proof shortcuts.
