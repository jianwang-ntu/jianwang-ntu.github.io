Research statement · 29 October 2026

Learning Reusable Reasoning for Reliable AI-Assisted Programming

Scope
Learning and evaluating reasoning for software understanding, generation, repair, and maintenance.
Aim
Learn transferable reasoning and sustain reliable agent behavior across extended software tasks.

I study reasoning for reliable AI-assisted programming: how AI systems understand software, learn from experience, and use that knowledge in unfamiliar settings. My proposed agenda connects two directions: learning reusable reasoning for programming and building reliable coding agents.

The first direction asks how models learn strategies that transfer to unfamiliar programs; the second asks how agents use those strategies to remain dependable over extended tasks and changing contexts. These questions connect informal reasoning about code and requirements with formal reasoning about specified properties. Execution, testing, static analysis, and formal verification provide complementary evidence, each with its own scope and assumptions.

Two connected directions
  1. Learning reusable reasoning for programming
  2. Building reliable coding agents

Research direction 1

Learning reusable reasoning for programming

How can models learn reasoning strategies that transfer across programs and tasks?

I aim to develop models that learn transferable ways of reasoning about programs. Here, reusable means strategies that transfer to unfamiliar programs. Solving a task involves choosing abstractions, investigating possible explanations, and revising an approach when evidence changes. A correct solution provides a learning target, but leaves open which decisions were useful and when they would apply elsewhere. This motivates my focus on learning from the process of solving a problem as well as its outcome.

My central hypothesis is that connecting reasoning decisions with observable feedback can improve transfer compared with learning from successful solutions alone. I would study how models learn from tests, execution traces, counterexamples, and checked proof steps. A diagnostic input, for example, can distinguish competing explanations of a failure; a proof obligation can reveal a missing condition in an argument. Building on these signals, I would investigate how models learn when to reuse a strategy, adapt it to new requirements, or abandon it.

I would test this hypothesis by comparing learning from decisions and feedback with learning from final solutions, using matched training tasks and budgets and reporting data-collection costs. Evaluation on held-out repositories and program families would control near-duplicates, retrieval access, and inference effort. Evidence for transfer would require higher independently assessed correctness at matched cost, or lower cost at matched correctness, beyond gains from retrieving similar examples or searching longer. Loop-invariant synthesis and revision would provide an initial setting; debugging, repair, and program understanding would test how far the learned strategies extend.

Research direction 2

Building reliable coding agents

How can coding agents remain dependable over extended tasks and changing contexts?

I aim to understand how coding agents turn individual reasoning steps into dependable behavior over extended software tasks. A useful local edit may conflict with a broader requirement, and a previously justified decision may become inappropriate as the context changes. This makes reliability a question about the coherence of the agent’s overall behavior, including how it adapts as its understanding and the software evolve.

This leads me to study adaptation, uncertainty, and recovery together. How can agents recognize when their assumptions no longer apply, revise their plans while preserving task objectives, and recover from unsuccessful actions? A complementary question is when the available evidence justifies continuing or claiming completion, and when human judgment is needed. The goal is sustained progress toward intended functional and security requirements, with claims proportionate to what has been established.

Evaluation would examine sustained task completion, regressions, recovery, and human review effort under comparable resources. Independent assessment would distinguish meeting the task’s requirements from merely passing the checks available to the agent. Formal guarantees, where sought, would remain conditional on the specified properties, models, assumptions, and trusted verification tools.

My long-term goal is AI systems that learn to solve unfamiliar programming problems and produce software people can depend on. Learning reusable reasoning provides the strategies; reliable agents must use and adapt them while remaining accountable to the task’s requirements.

Research foundation

My work in code-model evaluation, program repair, and loop-invariant synthesis provides the foundation. Related projects include Loop-R1, Defects4C, RATCHET, and execution-trace evaluation. The learning and agent methods described above are proposed research.

Related verification work provides concrete context: Anthropic and Theorem describe proofs of specified software properties under explicit execution assumptions; Theorem’s verified-stack proposal emphasizes reuse through verified component interfaces; and the Verus guide motivates protecting specifications and checking for invalid proof shortcuts.
